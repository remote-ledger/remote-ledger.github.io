# Imported from the JP1 device upgrades of hifi-remote.com's forum

Everything under `remotes/jp1/` except this file is generated by `rl import jp1` from a checkout
of the upstream repository. It is **not authored here**. SPEC.md R19 sets the conditions an import
must meet, and DESIGN.md section 28 describes how this one meets them.

- **Upstream:** <https://github.com/hifiremote/deviceupgrades>, the files of the forum's JP1 File
  Section, Device Upgrades (<http://www.hifi-remote.com/forums/dload.php?action=category&cat_id=4>),
  collected by the site's owner. The commit every file was built from is named in `IMPORT.md` and in
  every citation.
- **Licence:** none recorded. The files are what forum members programmed into JP1 remotes (a
  universal remote with a cable to a PC) so that they send one device's codes: tables of reference
  remote codes, which the repository treats as facts (DESIGN D110). The upstream repository states no
  licence either. Every citation names the commit and the file, so the source stays visible.

## What it imports

An upgrade names a device (`Description`), a JP1 *executor* (`Protocol.name`) with its device
parameters, and for each function an *OBC* byte. The executors' translators store the OBC reversed
(and, for NEC, complemented), and `src/remote_ledger/jp1/rmdu.py` undoes that. Only the executors
whose translators were **checked against the ledger's own codes** are read: the NEC family (NEC1,
NEC1 (No Repeats), NEC2, NECx1, NECx2), Sony (12/15 and 20), RC-5 (DESIGN.md section 32, whose rule is
RemoteMaster's own `Rc5Translator`) and four combos whose functions are two OBC bytes: Sony Combo (12/15/20), NEC1
Combo, NEC 4DEV Combo and NEC 4DEV Yamaha Combo, in its plain style (section 33); and RC-6, JVC and JVC Combo, Aiwa,
Denon and Denon Combo, Panasonic and Panasonic Combo (section 34); and NEC 2DEV Combo, Sharp Combo
and Sharp, Samsung36, Proton, F12, RECS80 (45) and Denon-K (section 35). Every other upgrade is counted by
executor in `IMPORT.md`, with the KeymapMaster `.txt` files, which are not read.

A file becomes one remote file per ledger protocol it sends, and every function a key with an `irp`
form, Plausible. The brand and category come from the forum's own master index, `jp1-master.xls`,
which `tools/jp1_master_to_csv.py` converted once to `sources/jp1-device-upgrades/` (the CSV and the
commit and workbook hash it was made from); an upgrade the index does not list takes the longest brand
of the index that begins its description, and one with no brand is listed, not imported. The model is
the description without its brand, and `controls` the description as written.
