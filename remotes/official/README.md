# Imported from manufacturers' own IR code tables

Everything under `remotes/official/` except this file is generated by `rl import official` from the
snapshots in `sources/official/`. It is **not authored here**. SPEC.md R19 sets the conditions an
import must meet, and DESIGN.md section 29 describes how this one meets them.

- **Upstream:** each manufacturer's own published table, so far **Marantz's** AV receiver and processor
  command charts (<https://www.marantz.com/>, the Archive pages of each model), **Anthem's** MRX and AVM
  IR hex sheet (<https://www.anthemav.com/>) and **Oppo's** remote code workbooks for its Blu-ray and Ultra HD
  players (Oppo's download host is gone, so they are the Wayback Machine's copies of
  `download.oppodigital.com`, DESIGN.md section 31) and **KEF's** one-page IR code sheets for its LS50 Wireless,
  LS50 Wireless II, LS60 Wireless, LSX, LSX II and XIO (PDFs on <https://assets.kef.com/> and the
  product pages of <https://www.kef.com/>, DESIGN.md section 62) and **JVC's** infrared remote control command emulation
  guide (long hex format) for its D-ILA projectors (DLA-HD, X and RS series, <https://support.jvc.com/>, DESIGN.md
  section 63) and **Arcam's** custom installation notes, whose RC-5 code tables cover its AVR, AV and SA amplifiers and
  receivers, the CDS50 and UDP411 players and the Solo and Solo Mini (PDFs on <https://www.arcam.co.uk/>, DESIGN.md
  section 64) and **Cambridge Audio's** two lists of NEC codes that carry no copyright notice (the AXR85 and AXR100 receivers, and
  the 752BD, CXU and CXUHD players' remotes; PDFs on <https://www.cambridgeaudio.com/>, DESIGN.md section 65) and **Hegel's** RC-5 code tables, a page for each of 14 products, the three of 2020 (seven products) with each code's Pronto hex (PDFs on
  <https://support.hegel.com/>, DESIGN.md section 66) and **Linn's** RC-5 code table for its network products (a LinnDocs wiki page,
  <https://docs.linn.co.uk/wiki/index.php/RC5_Codes>, and a PDF of Pronto hex, DESIGN.md section 67) and **Simaudio's** table of IR codes for its Moon amplifiers, CD and DVD players (a three-page PDF on
  <https://simaudio.com/>, DESIGN.md section 68). They are the makers' documents, not a third party's
  compilation, and they are still imported at Plausible: a manufacturer's word is one source (R19.3).
- **The pin:** a manufacturer's page is not a repository, so `sources/official/<maker>/` holds each document
  as the server sent it, the sheets the importer reads converted to CSV by
  `tools/official_sheets_to_csv.py` (a PDF page is its lines of text or its tables' cells), and a `MANIFEST.json` with each document's URL, size and SHA-256,
  each CSV's source and SHA-256, and the retrieval date. The importer refuses a file whose hash differs, and
  every citation names the first eight hex digits of its document's hash.
- **Licence:** none recorded. A manufacturer's table of the codes its product accepts is a table of reference
  remote codes, which the repository treats as facts (DESIGN D110). Anthem's separate PDF for the MRX SLM
  says it may not be reproduced without written permission; it is not imported. **JVC's guide says the opposite**
  ("This document may be distributed freely, as long as the author and copyright information remain intact", (c) 2012
  JVC, Dale McWilliams, JVC Consumer A/V Group): it is kept whole in `sources/official/jvc/` and the bundle's notices
  name the author and the copyright.

## What it imports

One file per model, named as the manufacturer names it (`SR5004`, `AVM 70`), carrying the commands the
manufacturer's chart marks that model as accepting. Marantz publishes the signal of a command as Pronto hex
and imports it verbatim as a `pronto` form; a plain RC-5 command with no hex is an `irp` RC5 form; an RC-5
*extension* command (Marantz's RC-5x) with no hex is listed in `IMPORT.md`, because the ledger has no
protocol for it. Anthem's codes are NEC1, read from the sheet's device and data columns and **checked
against its own Pronto hex**. A key the sheet contradicts itself on is Untested and says so. Oppo's are NEC1
from the hex column of each of a player's three code sets (`BDP-103`, `BDP-103 [code set 2]`...), **checked against
the decimal column, the TSU3000 string and the classic Pronto hex**: where the signal itself disagrees the key is
Untested, and where only a derived column has a typo (seven rows) it stays Plausible and the citation says so.
KEF's are NEC1 too, one file a product (`LSX II`, `XIO`): each sheet gives a factory code (`0x01`) and a function code
for each key, **in the other bit order than the ledger's NEC1** (the device is `0x80` and `0x40` is the function `0x02`),
which the IR Blaster database's KEF remote confirms for the eight codes it holds. JVC's are the ledger's `JVC` protocol
(device 115, a function number), one file for each of the 22 projectors on the guide's cover, **checked against the guide's
own Pronto hex**: where the hex does not say the stated code (three entries have damaged text) the key is Untested. Arcam's are the ledger's `RC5` (the system code the device, the
command the function), one file for each product a document lists (`AVR450`, `SA20`, `Solo Mini`...), **each row's decimal
and hex checked against each other**; a function a table says is `(not AVR5, AVR10)` or `(AVR450/750 only)` is left out of
the files it is not for. Cambridge's are NEC1 (the address the device, its complement the subdevice, the function), one file for each
product (`AXR85`, `CXU`...); **the AXR85's 23 codes are all in the IR Blaster database's AXR85 remote under the same names**. Hegel's are the ledger's `RC5` too, one
file for each product (`H190`, `Röst`, `Mohican`...), **where a page has the Pronto hex it is decoded and checked against the row** (all 67
agree, and are the ledger's own compile of the code but for the last gap) and the `(alt)` row is the toggle bit's twin and no key; a
product's older table that contradicts its newer one is kept apart as `H590 (2019 table)_questionable`. Linn's are `RC5` too, a file for each
of the three device addresses of the table (`DS/DSM Amplifier` 0x10, `CD` 0x14, `DVD` 0x19), a cell's first line the label and the rest notes. Simaudio's are `RC5` (the amplifiers' system 16, the CD players' 20) and `RC6` (the DVD
players' control code 4), a file for each Moon product the page names, **70 distinct codes of which 69 are held by other sources' remotes**.

`IMPORT.md` lists everything a document holds that does not become a key, with the reason.
