# Imported from Flipper-IRDB

Everything under `remotes/flipper-irdb/` except this file and `LICENSE` is generated by `rl import flipper-irdb` from the files pinned in
`sources/flipper-irdb/`. It is **not authored here**. SPEC.md R19 sets the conditions an import must meet, and DESIGN.md section 96 describes
how this one meets them.

- **Upstream:** <https://github.com/Lucaslhm/Flipper-IRDB>, a community collection of Flipper Zero `.ir` files: a file for a device and in it a
  button for each code. The commit every file was read at is named in `IMPORT.md` and in every citation.
- **Licence:** CC0-1.0, from 2025-08-07 only: that day the repository added its LICENSE file and a note in its README that a contributor
  agrees to license their work under CC0 (its pull request #960). `LICENSE` is the upstream's, copied verbatim.
- **What is here is only what that licence covers.** A file that was written or added before it has no licence of its own and is not here (SPEC
  section 4). `tools/fetch_flipper.py` keeps a file when the commit that added it came after the licence commit and was not authored before it
  (a pull request written earlier and merged later is not covered), when a rename does not trace it back to an older file, and when its
  content is in no earlier commit. `sources/flipper-irdb/MANIFEST.json` lists every file kept with its adding commit, and every file that
  was not kept with the reason.

## What an imported remote is, and is not

- **A file of Flipper-IRDB is one device's remote; a remote here is one protocol of it.** A file that has NEC buttons and raw ones is two
  remotes (`Model [NEC1]`, `Model [raw 38000 Hz]`), as the JP1 import's are, because a remote file has one protocol (R3).
- **A parsed button is a ledger code.** Flipper's `protocol`, `address` and `command` are mapped by rules read from the firmware's decoders
  (`NEC` is `NEC1` with the address's complement as the subdevice, `NECext` is `NEC1` or, when the fourth byte is not the complement of the third,
  `NEC1-f16`, `Samsung32` is `NECx2`, `SIRC`, `SIRC15` and `SIRC20` are `Sony12`, `Sony15` and `Sony20`, `RC5` and `RC5X` are `RC5`, `RC6` is
  `RC6`, `Pioneer` is `Pioneer-2Part`, and `Kaseikyo` is `Panasonic`, `JVC-48` or `Denon-K` by its vendor) and checked against the firmware's own
  captures (`tools/flipper_capture_audit.py`). A button whose protocol is not one of these, or whose address or command does not fit it, is
  listed in `IMPORT.md` with the reason, not dropped.
- **A raw button is a raw form that ends on a mark.** Flipper's raw data has no final space; the firmware sends a silence of 180 ms before every raw
  transmission, and that is the closing gap (`truncated`, with the firmware's lines as its source). The duty cycle is not kept.
- **Every form is `plausible`**: one source that nothing has cross-checked (SPEC section 5). The people who submitted a file are not named in it;
  a citation names the commit that added it.
- **Names.** The brand is the directory under the category (`ACs/Daikin/...`), the model the file's name without the brand, an underscore a space.
  A model another source already has keeps this file under `<model> (Flipper-IRDB)` (R15).
- **Nothing is dropped silently.** `IMPORT.md` lists every file and every button that yields nothing.
- Hand edits to a generated file are overwritten by the next import.
